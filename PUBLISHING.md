# Подготовка к BB Store

Статус: рабочий прототип; репозиторий разработки приватный. Публичного релиза,
тегов и заявки в marketplace пока нет. Наличие репозитория не означает готовность
установки на чужую машину.

## Предлагаемый первый выпуск

Linux-машина с Android SDK/KVM; BB Desktop или веб-клиент на любой платформе.
Трансляция через частную сеть Tailscale. Управляется один общий выбранный
эмулятор на bridge. Windows/macOS как Android-хосты и независимые экраны
зрителей можно добавить после первой версии; это не обязательные условия Store.

## До публичного релиза

1. **Установка на чистой машине.** Добавить проверку ОС, SDK/ADB, KVM и всех
   зависимостей bridge. Настройка должна объяснять недостающее и предоставлять
   воспроизводимый запуск, без ручного копирования scrcpy в каталог исходников.
   Системные пакеты, SDK и Tailscale настраивать только явным действием пользователя.
2. **Параметры машины.** Личный домен и пути убраны из исходников и README
   перед первым push. Origin задаётся через окружение. Осталось перенести
   пути инструментов, порты и X display в понятную конфигурацию.
3. **Доступ и безопасность.** Проверить аутентификацию HTTP и WebSocket,
   включая Origin WebSocket. Сейчас POST проверяет Origin, VNC на loopback
   работает без пароля и полагается на Tailscale. Для общего распространения
   нужны явная модель доступа и проверка обходных путей. Не публиковать VNC
   или bridge напрямую в интернет. Clipboard и управление должны иметь те же
   ограничения доступа, что экран.
4. **Жизненный цикл.** Статусы bridge/SDK/AVD, запуск и остановка bridge,
   восстановление после обрыва/перезагрузки, обработка занятых портов и X display.
   Дождаться готовности Android, блокировать повторный запуск одного AVD,
   показывать сбой загрузки и сохранять диагностический журнал.
5. **Проверки и CI.** npm ci, typecheck, i18n-тесты, backend-тесты с websockify,
   сборка BB, отдельная установка из Git с production-зависимостями. Проверить
   на чистом Linux, в веб-клиенте BB, в светлой/тёмной/пользовательской теме,
   выбор языка, clipboard Unicode, переподключение и несколько зрителей.
6. **Упаковка и лицензии.** Выбрать лицензию проекта; проверить условия
   распространения заимствованных иконок и сторонних компонентов. Добавить
   notices, при необходимости. Обновить package metadata и честно зафиксировать
   минимальную проверенную версию BB/SDK.

## Материалы и процесс marketplace

- Публичный Git-репозиторий и неизменяемый тег релиза, например v0.1.0.
- PLUGIN_OVERVIEW.md с назначением, требованиями, установкой, моделью доступа
  и ограничением общего выбранного экрана.
- Entry `android-emulator`: автор, source, категория, описание и иконка.
- Реальные скриншоты внутри BB, без личных данных. Текущие снимки панели
  480 px шириной не подходят под минимальные 1200 px для community-карточки.
- Сверить текущие требования marketplace и выполнить его проверки, затем PR.

Публичный релиз и подача в Store — отдельный шаг после согласования.

Актуальные источники:

## Решения для обсуждения

Рекомендация: начать с Linux + Tailscale, обеспечить установку bridge через
понятный мастер и выпускать как experimental. Не расширять поддержку ОС до
проверки этой установки на чистой машине. Отдельно выбрать лицензию и решить,
остаётся ли Tailscale обязательным или нужен транспорт через BB.
